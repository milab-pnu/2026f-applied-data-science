9주차에는 선형회귀로 펭귄 몸무게를, 10주차에는 로지스틱 회귀와 트리 앙상블로 Chinstrap 여부를 예측했다.
XGBoost는 [10b §3.1](/lecture/2026f-applied-data-science/10b-trees-xgboost-shap#31-잔차를-맞추는-트리)에서 본 것처럼 잔차를 맞추는 트리를 쌓으므로 몸무게 같은 연속값에도 그대로 쓸 수 있다.
그래서 이번 주는 몸무게 예측으로 돌아와 선형회귀와 XGBoost를 한자리에 모은다.
이 후보들은 모두 지금 가진 훈련 데이터만 보고 매개변수를 맞추고, XGBoost라면 트리의 깊이와 개수 같은 초매개변수(학습 전에 사람이 정하는 값)도 검증으로 골라야 한다.

**TabPFN**(Tabular Prior-data Fitted Network)은 방식이 다르다.[^tabpfn]
수많은 가상의 표 문제로 미리 학습해 두고, 새 표를 만나면 그 표의 훈련 행을 입력으로 받아 곧바로 예측한다.
이처럼 대규모 사전학습으로 여러 문제에 두루 쓸 능력을 얻은 모델을 **파운데이션 모델**(foundation model)이라 부른다.

TabPFN v2 논문은 1만 행 이하의 표에서 초매개변수 탐색 없이 기본 설정만으로 기존 방법을 앞섰고, 분류에서는 평균 2.8초 만에 4시간 튜닝한 부스팅 등 기존 방법들의 앙상블보다 좋았다고 보고했다.[^tabpfn]

**읽기 자료**: Hollmann 등의 [Accurate predictions on small data with a tabular foundation model](https://doi.org/10.1038/s41586-024-08328-6).[^tabpfn]
교재에는 이 모델을 다루는 장이 없으니, 원논문의 Fig. 1·2와 Methods의 사전분포 설명을 먼저 읽고 나머지는 필요한 만큼 참고한다.

## 1. 모델을 맞추는 두 방식

XGBoost는 `fit`에서 이 표의 훈련 행에 맞춰 트리를 쌓고, 다른 표를 만나면 처음부터 다시 쌓는다.
TabPFN은 가중치를 사전학습에서 한 번 맞춘 뒤 새 표에서는 바꾸지 않는다.
이 표의 훈련 행은 여전히 필요하지만, 예측할 행과 함께 입력으로 들어간다.

| | XGBoost | TabPFN |
|---|---|---|
| 가중치를 맞추는 자료 | 이 표의 훈련 행 | 사전학습에 쓴 1억 개가 넘는 합성 표 |
| 이 표의 훈련 행이 쓰이는 때 | `fit`에서 트리를 만들 때 | `predict` 때 예측할 행과 함께 |
| 초매개변수 | 검증으로 고른다 | 기본값을 그대로 쓰는 경우가 많다 |
| 계산이 몰리는 때 | 학습 | 예측 |

## 2. TabPFN의 사전학습과 예측

### 2.1 합성 데이터 사전학습

TabPFN의 사전학습 자료는 실제 데이터가 아니라 컴퓨터가 만든 **합성 표**(synthetic dataset)다.
합성 표 하나가 예측 문제 하나다.
표마다 인과 그래프(변수 사이의 원인과 결과를 화살표로 이은 그래프)를 무작위로 하나 만들어 값을 흘려보낸 뒤, 그 가운데 몇 노드를 특성으로, 한 노드를 결과로 고른다(원논문 Fig. 2).
결과 노드가 특성 노드의 원인 쪽에 놓이기도 하고 노드 사이의 함수와 잡음도 표마다 달라서, 어떤 표는 입력과 결과가 거의 직선 관계이고 어떤 표는 곡선이나 임계값을 가진다.
이런 생성 규칙들이 어떤 분포에서 뽑히는지를 정한 가정이 **사전분포**(prior)다.
Prior-data Fitted Network라는 이름은 "사전분포에서 뽑은 표들로 맞춘 신경망"이라는 뜻이다.

학습 과제는 각 합성 표에서 일부 행의 정답을 가리고, 나머지 행의 특성과 정답을 보고 가린 정답을 맞히는 것이다.
가린 정답에 대한 예측이 틀린 만큼 손실을 매기고, 그 손실이 줄도록 가중치를 갱신한다.
손실은 [10a §1.3](/lecture/2026f-applied-data-science/10a-binary-classification#13-로그-손실과-학습)의 로그 손실과 같은 형태다.
분류라면 정답 범주에 준 확률에 −log를 매기고, 회귀라면 결과값의 범위를 5,000개 구간으로 나눠 구간마다 확률을 낸 뒤 정답이 든 구간의 확률에 −log를 매긴다.
이 과정을 1억 개가 넘는 표에서 반복하면, 모델은 표 하나의 관계보다 "정답 붙은 행 몇 개를 보고 새 행의 결과를 추론하는 방법"을 익힌다.[^tabpfn]

여러 유형의 연습문제로 문제 푸는 요령을 익힌 학생에 비유할 수 있다.
실제 문제가 연습문제와 비슷한 구조라면 처음 보는 문제도 잘 푼다.
반대로 실제 데이터의 관계가 사전분포가 거의 만들지 않는 모양이라면 성능이 떨어질 수 있다.<Sidenote>초기 TabPFN(v1, 2023)의 한 체크포인트를 1차원 이진 분류 문제로 시험한 분석에서는 훈련 데이터의 주기적 패턴을 따라간다는 증거를 찾지 못했다.[^tabpfn-analysis] 초기 가중치의 관찰이지만, 사전분포가 잘 만들지 않는 관계에서 약해질 수 있다는 예다.</Sidenote>

### 2.2 새로운 표에서의 문맥 학습

새 표의 예시를 입력으로 받아 예측하는 방식을 **문맥 학습**(in-context learning)이라 한다.
챗봇에 "사과 → apple, 하늘 → sky" 같은 예시 몇 쌍을 보여 주고 "바다 →"를 물으면, 가중치를 바꾸지 않고도 예시의 형식을 따라 답한다.
TabPFN에서는 정답이 붙은 훈련 행이 예시 쌍이고, 정답을 모르는 행이 새 질문이다.

챗봇 비유에는 한계가 있다.
챗봇은 사람의 글로 사전학습해 "사과"의 뜻을 알지만, TabPFN은 합성 표만 보았으므로 "펭귄"이나 "몸무게"가 무엇인지 모른다.
열 이름이 아니라 값들이 함께 변하는 패턴만 본다.

예측할 펭귄의 행은 훈련 행들을 똑같이 참고하지 않는다.
관련이 깊어 보이는 행을 더 크게 참고하고, 이렇게 입력의 다른 부분에 참고 비중을 나눠 주는 계산을 **attention**이라 한다.
TabPFN은 attention을 여러 층 쌓은 신경망 구조인 트랜스포머(Transformer)로 만들었다.
v2는 표의 칸 하나하나를 입력 단위로 삼아, 같은 행의 다른 특성을 참고하는 attention과 같은 열의 다른 행을 참고하는 attention을 층마다 번갈아 쓴다.[^tabpfn]
무엇을 관련이 깊다고 볼지, 예를 들어 날개 길이가 비슷한 행인지 같은 종인 행인지는 사람이 정하지 않고 사전학습에서 익힌 가중치가 정한다.

TabPFN의 예측이 분포로 나온다는 점은 작은 예에서 잘 보인다.
훈련 행 두 개가 각각 날개 길이 180 mm에 몸무게 3,500 g, 220 mm에 5,000 g이고 새 펭귄의 날개 길이가 200 mm라고 하자.
두 점을 잇는 직선이라면 4,250 g 하나를 내놓는다.
TabPFN v2(`random_state=0`, Intel Core Ultra 5 CPU)에 두 훈련 행을 문맥으로, 새 행의 날개 길이를 질문으로 넣었다.
예측 분포의 확률은 3,500 g 근처(3,300–3,700 g)에 약 3분의 1, 5,000 g 근처(4,800–5,200 g)에 약 5분의 1이 몰렸고, 4,250 g 근처(4,050–4,450 g)에는 2%쯤만 놓였다.
문맥의 두 몸무게가 그대로 유력한 후보가 된 것이다.
이처럼 봉우리가 둘인 분포에서는 봉우리마다 실리는 확률이 장비나 `random_state`에 따라 꽤 달라진다.

문맥 학습은 **미세조정**(fine-tuning)과 다르다.
미세조정은 사전학습한 가중치를 새 데이터의 손실로 조금 더 갱신하지만, 문맥 학습은 가중치를 그대로 둔다.
TabPFN은 기본적으로 문맥 학습으로 쓰고, 필요하면 미세조정도 할 수 있다.[^tabpfn]
그래서 scikit-learn식 `fit(X, y)`는 이름과 달리 가중치를 갱신하지 않는다.
훈련 행을 저장하고 입력 전처리를 준비할 뿐이며, `predict`를 부를 때 저장한 훈련 행과 예측할 행이 함께 신경망을 통과한다.
TabPFN은 예측할 때마다 훈련 행 전체를 문맥으로 처리하므로 훈련 행이 많아질수록 예측이 비싸진다.

정답을 언제 보여 주는지도 단계마다 다르다.

| 단계 | 모델에 들어가는 정보 | 정답의 쓰임 |
|---|---|---|
| 사전학습 | 합성 표의 훈련 행, 가린 행의 특성 | 가린 정답으로 손실을 계산해 가중치 갱신 |
| 새 표에서 예측 | 이 표의 훈련 행(특성과 정답), 예측할 행의 특성 | 훈련 행의 정답만 문맥으로 들어간다 |
| 성능 평가 | 없음 | 검증·테스트 행의 정답은 예측이 끝난 뒤 채점에만 쓴다 |

검증·테스트 행의 정답이 문맥에 섞이면 [09a §1.2](/lecture/2026f-applied-data-science/09a-prediction-and-linear-regression#12-훈련-검증-테스트)의 누출과 같은 문제가 생긴다.

## 3. 기존 후보와의 비교

TabPFN도 다른 후보와 같은 조건에서 비교한다.
[09b §2.2](/lecture/2026f-applied-data-science/09b-features-and-regularization#22-교차검증과-선택)와 같은 훈련 239마리와 같은 5폴드 분할을 쓰고, 특성도 같은 넷(날개 길이, 부리 길이, 부리 깊이, 종)을 쓴다.[^penguins]
테스트 103마리는 선택에 쓰지 않고 최종 평가에 남겨 둔다.

전처리 요구는 모델마다 다르다.
선형회귀와 XGBoost에는 종을 표시 변수로 바꿔 넣는다.
TabPFN은 결측값 처리, 범주형 변수 변환, 척도 조정을 내부에서 하므로 종을 문자열 그대로 넣었다.[^tabpfn]
문자열 열은 범주형으로 보고 순서를 무작위로 섞은 정수 코드나 표시 변수로 바꿔 쓰므로, 종 사이에 크기 순서가 생기지 않는다(0·1·2로 바꿔 넣어도 값이 셋뿐이라 범주형으로 추정되어 결과가 같았다).[^repo]
이 내부 전처리도 `fit`에 넣은 행에서 추정하므로, 교차검증에서는 `fit`에 그 폴드의 훈련 부분만 넣는다.

```python
import pandas as pd
from sklearn.model_selection import train_test_split, KFold, cross_val_score
from tabpfn import TabPFNRegressor
from tabpfn.constants import ModelVersion

url = ("https://raw.githubusercontent.com/allisonhorst/palmerpenguins/"
       "main/inst/extdata/penguins.csv")
cols = ["flipper_length_mm", "bill_length_mm", "bill_depth_mm", "species"]
d = pd.read_csv(url).dropna(subset=cols + ["body_mass_g"])
train, test = train_test_split(d, test_size=0.3, random_state=0)
X, y = train[cols], train["body_mass_g"]  # 종은 문자열 그대로

model = TabPFNRegressor.create_default_for_version(ModelVersion.V2, random_state=0, device="cpu")
cv = KFold(5, shuffle=True, random_state=0)
mae = -cross_val_score(model, X, y, cv=cv, scoring="neg_mean_absolute_error")
print(mae.round(0), mae.mean().round(1))  # 폴드별 MAE와 평균
```

TabPFN은 기본 설정 그대로 쓰고 가중치 버전만 v2로 지정했다(이유는 §4).
가중치는 고정이지만 TabPFN은 특성 순서와 전처리를 조금씩 달리한 입력으로 여러 번 예측해 평균하므로, 같은 결과를 얻도록 `random_state`를 고정했다.
`predict`는 기본으로 §2.2와 같은 예측 분포의 평균을 점 예측으로 돌려주고, `output_type="median"`을 주면 중앙값을 돌려준다.[^repo]
위 코드의 MAE는 기본값인 평균으로 계산한 것이고, 중앙값으로 바꿔도 247 g으로 거의 같았다.

XGBoost는 깊이(2, 3, 4), 트리 수(50, 100, 200, 400), 학습률(0.03, 0.1)의 조합 24개 가운데 MAE가 가장 작은 것을 골랐다.
이 선택도 폴드마다 그 훈련 부분 안에서 다시 5폴드 교차검증으로 했는데, 이렇게 교차검증 안에 교차검증을 한 겹 더 두는 것을 **중첩 교차검증**(nested cross-validation)이라 한다.
코드로는 `GridSearchCV(XGBRegressor(random_state=0), grid, cv=KFold(5, shuffle=True, random_state=0), scoring="neg_mean_absolute_error")`를 바깥 `cross_val_score`에 넣었다.
시간은 같은 노트북(Apple M3) CPU에서 쟀고, TabPFN은 tabpfn 9.2.0 패키지와 v2 가중치를 썼다.
결과는 다음과 같다.

| 후보 | 5폴드 CV MAE (g) | 폴드 사이 표준편차 (g) | 예측 한 건에 걸린 시간 |
|---|---|---|---|
| 기준 모델(훈련 평균) | 695 | 43 | |
| 선형회귀 | 257 | 29 | 0.0002초 |
| XGBoost | 274 | 34 | 0.0003초 |
| TabPFN v2 | 248 | 28 | 0.28초 |

초매개변수를 하나도 고르지 않은 TabPFN의 오차가 가장 낮았다.
선형회귀보다 평균 9 g 낮고 다섯 폴드 모두에서 3–15 g씩 낮았으며, 튜닝한 XGBoost는 오히려 선형회귀보다 약 17 g 나빴다.
XGBoost가 뒤진 까닭을 따로 확인하지는 않았지만, 이 자료에서는 종을 나누고 나면 몸무게가 치수에 대체로 직선으로 늘어난다([09b §1.3](/lecture/2026f-applied-data-science/09b-features-and-regularization#13-비선형-특성과-상호작용)).
트리는 이런 관계를 계단 모양으로 근사하므로, 191마리 남짓한 훈련 부분에서는 직선보다 불리했을 수 있다.

계산이 몰리는 때는 §1의 표대로 갈린다.
239마리 전체에서 XGBoost의 격자를 고르려면 24개 조합을 5폴드로 120번 학습해야 하지만, TabPFN의 `fit`은 훈련 행을 저장하고 전처리를 준비하는 데 그친다.
다른 컴퓨터의 CPU(Intel Core Ultra 5)에서 재 보면 XGBoost의 격자 탐색은 약 20초, TabPFN의 `fit`은 0.1초가 안 걸렸다.

반면 TabPFN의 예측 한 건은 선형회귀보다 천 배 넘게 느렸다.
대부분은 한 번 부를 때 드는 고정 비용이라 103마리를 한 번에 예측해도 0.30초로 거의 같았다.
문맥이 되는 훈련 행 수에는 민감해서, 위의 다른 CPU에서 4특성 합성 표로 재 보면 예측 한 건에 1,000행은 239행의 약 5배, 3,000행은 약 20배가 걸렸다.
하루에 몇 번 예측하는 용도라면 문제가 안 되지만 초당 수천 건을 처리해야 한다면 부담이 된다.
또 이 패키지는 CPU에서 v2를 쓸 때 훈련 행이 200개를 넘으면 느릴 수 있다고 경고하고, 1,000개를 넘으면 기본으로 오류를 낸다.[^repo]
더 큰 표는 GPU를 쓰거나, `ignore_pretraining_limits=True` 또는 환경변수 `TABPFN_ALLOW_CPU_LARGE_DATASET=1`로 제한을 푼다.

SHAP으로 설명할 때는 이 비용이 더 커진다.
트리 구조를 이용하는 빠른 계산을 쓸 수 없어 Kernel SHAP 같은 모델 무관 방법([09c §4.1](/lecture/2026f-applied-data-science/09c-shapley-and-shap#41-kernel-shap))으로 특성을 가린 조합마다 예측을 다시 해야 하므로, 설명할 펭귄 수와 배경 데이터 크기를 작게 잡는다.

## 4. 버전과 이용 조건

TabPFN v2 논문은 예측 속도와 메모리를 스스로 한계로 밝혔다.[^tabpfn]
그 뒤로 2.5와 2.6을 거쳐 더 큰 표를 겨냥한 TabPFN-3과 3.5가 나왔다.
v2 뒤에 나온 2.5부터 3.5까지의 가중치는 모두 비상업 라이선스이고 내려받기 전에 로그인과 라이선스 동의를 거쳐야 하므로, 이 노트는 별도 동의 없이 내려받아 누구나 바로 재현할 수 있는 v2를 썼다.[^repo]
어느 버전이든 벤치마크의 우위가 프로젝트 데이터에서도 나오는지는 다른 후보와 같은 분할, 같은 계산 예산으로 직접 확인한다.
결과와 함께 패키지와 실제로 불러온 가중치의 버전, 그리고 로컬에서 돌렸는지 외부 서비스를 불렀는지를 남긴다.
외부 서비스를 쓰면 데이터가 밖으로 나가므로 공개할 수 없는 자료에는 실행 위치부터 정한다.

<Details summary="버전별 범위와 이용 조건">

`TabPFNRegressor()`를 버전 지정 없이 부르면 최신 기본 가중치가 쓰이므로, 어떤 가중치인지부터 확인한다.

| 버전 | 보고된 범위 | 현재 패키지에서 | 가중치 이용 조건 |
|---|---|---|---|
| v2 (2025) | 최대 1만 행, 500 특성[^tabpfn] | `ModelVersion.V2`로 지정 | Prior Labs License(Apache 2.0에 출처 표시 조건 추가), 별도 동의 없이 내려받음[^repo] |
| TabPFN-3 (2026) | 최대 100만 훈련 행 실험[^tabpfn3] | 직전 기본값, `ModelVersion.V3` | 비상업 라이선스, 내려받기 전 라이선스 동의[^repo] |
