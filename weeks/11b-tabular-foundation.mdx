표 형식 데이터는 행에 관측을, 열에 특성과 예측 대상을 담는다.
앞선 노트에서 살펴본 선형회귀와 랜덤 포레스트, XGBoost는 각각 현재 문제의 학습 데이터로 모델을 맞춘다.
이번에는 다양한 가상의 표 문제를 미리 학습한 모델이 새로운 표에 어떻게 적용되는지 살펴본다.
대표 사례는 **TabPFN**(Tabular Prior-data Fitted Network)이다.[^tabpfn]

파운데이션 모델은 여러 문제에 공통으로 쓸 수 있는 능력을 대규모 사전학습으로 얻고, 이를 새로운 문제에 활용하도록 만든 모델이다.
표 형식 파운데이션 모델에서는 문장이 아니라 여러 형태의 표 예측 문제가 사전학습의 대상이다.
이름에 파운데이션이 붙었다고 해서 모든 표에서 정답을 알거나 새로운 표의 검증이 불필요해지는 것은 아니다.

앞 노트에서 같은 예측 문제의 후보를 비교했다면, 여기서는 그 후보 목록에 사전학습된 모델을 하나 더 넣는다.
먼저 이 모델이 새 표의 정답을 어떻게 활용하는지 이해하고, 그다음 기존 후보와 같은 조건에서 비교한다.

## 1. 표 형식 예측의 어려움

펭귄 한 마리가 한 행이고 부리 길이, 부리 깊이, 날개 길이가 열이라면 몸무게를 예측하는 표를 만들 수 있다.
표마다 행의 수, 열의 수, 특성의 단위와 결측 패턴, 결과를 결정하는 관계가 다르다.
어떤 데이터는 특성과 결과가 거의 직선 관계지만 다른 데이터에는 임계값이나 복잡한 상호작용이 있을 수 있다.

XGBoost는 현재 학습 데이터에서 오차를 줄이도록 트리를 차례로 추가한다.
새 문제로 바뀌면 그 문제의 학습 데이터를 이용해 다시 모델을 맞춘다.
TabPFN은 다른 접근을 취한다.
미리 다양한 표 문제에서 학습한 하나의 모델에 현재 문제의 예시를 주고, 그 예시를 조건으로 새 행을 예측한다.
현재 문제의 예시를 사용하므로 레이블이 전혀 필요 없는 예측은 아니다.

## 2. TabPFN의 사전학습과 예측

### 2.1 합성 데이터 사전학습

TabPFN v2 연구는 다양한 구조의 **합성 데이터셋**(synthetic dataset)을 생성하여 사전학습에 사용한다.
각 데이터셋은 특성, 결과, 둘 사이의 생성 관계가 다른 하나의 예측 문제다.
모델은 한 문제에서 레이블이 알려진 행을 참고해 다른 행의 결과를 예측하는 과정을 여러 문제에 걸쳐 반복하며 매개변수를 학습한다.[^tabpfn]
예를 들어 한 가상 표에서는 입력과 결과가 대체로 직선 관계이고 다른 표에서는 곡선 관계이며, 각 표의 잡음 크기도 다를 수 있다.
각 표에서 일부 정답을 보여 주고 나머지를 예측하는 과정을 반복하면, 새로운 표에서도 주어진 예시를 바탕으로 관계를 추론하도록 학습할 수 있다.
이런 가상 문제의 구조와 매개변수를 만들어 내는 가정의 분포를 사전분포(prior)라고 한다.
사전분포와 실제 문제가 많이 다르면 예측이 어려울 수 있으므로 프로젝트 데이터에서 따로 평가한다.

위에서는 결과가 알려진 합성 문제로 가중치를 학습하고, 아래에서는 새로운 표의 알려진 행들을 문맥으로 사용해 정답이 없는 행을 예측한다.
오른쪽 패널은 이 절차를 수행하는 모델 내부 구조를 보여 준다.

이를 비유하면 여러 형태의 연습문제를 풀며 문제를 푸는 방법을 익히는 과정이다.
실제 문제에서도 비슷한 관계가 나타나면 사전학습이 도움이 될 수 있다.
그러나 합성 문제의 생성 방식은 현실의 가능한 모든 관계를 담지 못하므로, 사전학습에 쓰인 가정과 실제 데이터가 다르면 성능이 저하될 수 있다.
이 비유는 모델이 실제 데이터의 인과관계를 발견했다는 뜻이 아니다.

합성 문제가 왜 중요한지 한 가지 극단적인 예로 생각해 보자.
사전학습 문제가 대체로 날개 길이가 길수록 몸무게가 커지는 관계만 포함한다면, 새로운 표에서 반대 관계나 복잡한 주기 패턴을 만나 예측하기 어려울 수 있다.
실제 TabPFN의 합성 문제들은 이보다 다양하며, 이 예는 모델의 실제 학습 범위를 묘사한 것이 아니라 사전학습 분포와 새 문제 사이의 차이를 설명하기 위한 것이다.
초기 TabPFN을 단순한 분류 문제로 조사한 독립 해설은 일부 반복 패턴에서 한계를 관찰했다.
이는 특정 초기 가중치의 관찰이므로 이후 버전 전체에 그대로 일반화해서는 안 된다.[^tabpfn-analysis]

### 2.2 새로운 표에서의 문맥 학습

**문맥 학습**(in-context learning)은 현재 문제의 예시를 입력 문맥으로 사용해 예측하는 방식이다.
펭귄 예시에서 몸무게를 알고 있는 학습 행들과, 몸무게를 모르는 새 행의 측정값을 모델에 제공한다.
사전학습된 모델은 이 예시들을 바탕으로 새 행의 몸무게를 예측한다.
분류라면 학습 행의 클래스 정보를 참고해 새 행의 클래스 확률을 출력할 수 있다.

예를 들어 학습 행 두 개에 날개 길이와 몸무게가 각각 180 mm, 3,500 g과 220 mm, 5,000 g으로 기록되어 있고, 새 펭귄의 날개 길이가 200 mm라고 하자.
모델에 앞의 두 행은 입력과 정답을 함께, 새 행은 입력만 제공한다.
모델은 이 문맥을 바탕으로 새 행의 몸무게를 출력한다.
이것은 입력 형태를 설명하기 위한 작은 예이며, 실제 예측이 두 몸무게의 평균으로 계산된다는 뜻은 아니다.

이때 모델이 참고할 수 있는 정보와 나중에 채점할 정보를 구분하자.
두 학습 행은 날개 길이와 몸무게가 함께 알려진 예시이고, 200 mm인 새 행에는 날개 길이만 제공한다.
나중에 새 펭귄을 실제로 재어 4,100 g이라는 결과를 얻었다면, 예측값이 4,300 g일 때 절대 오차는 200 g이다.
4,300 g과 4,100 g은 설명을 위해 임의로 정한 숫자이며 TabPFN의 실제 실행 결과가 아니다.
이 평가는 정답 4,100 g을 예측할 때 숨겼을 경우에만 의미가 있다.

사전학습된 매개변수를 새 데이터에 맞추어 기울기 기반으로 갱신하는 **미세조정**(fine-tuning)과는 구분해야 한다.
기본적인 문맥 학습에서는 사전학습된 가중치를 고정한 채 현재 표의 학습 행을 예시로 제공한다.
구현에서 `fit`을 호출하더라도 그 이름만으로 XGBoost와 동일한 방식의 가중치 학습이 일어난다고 해석하지 않는다.
TabPFN v2는 트랜스포머를 사용하며 별도 미세조정도 가능한 모델이다.[^tabpfn]

실무 코드에서 `fit(X_train, y_train)`은 현재 문제의 학습 특성과 정답을 모델이 이후 예측에 사용할 수 있도록 준비하는 단계다.
이어 `predict(X_valid)`를 호출하면 준비된 학습 예시를 바탕으로 검증 행의 결과를 예측한다.
이때 `y_valid`는 예측에 넣지 않고 예측이 끝난 후 점수를 계산할 때만 쓴다.
기본 문맥 학습에서는 학습 행을 활용하더라도 사전학습 가중치를 현재 표의 오차에 맞추어 반복 갱신하는 것과 구별한다.
다만 버전과 설정에 따라 전처리, 캐시 등 구체적인 준비 과정은 다를 수 있다.[^repo]

[공식 회귀 예제](https://github.com/PriorLabs/TabPFN/blob/main/examples/tabpfn_for_regression.py)에서는 공개 당뇨병 데이터로 `fit`, `predict`, MAE 계산을 확인할 수 있다.
예제의 데이터는 펭귄 자료와 다르지만 학습 입력과 예측할 입력을 구분하는 절차는 같다.
예제처럼 테스트 점수를 살펴보며 설정을 고르면 그 데이터는 검증에 쓰인 것이므로, 실제 모델 비교에서는 설정을 고를 검증 자료와 마지막 테스트 자료를 따로 둔다.
첫 실행에는 가중치 다운로드가 필요할 수 있으며 설치 방법과 하드웨어 요구 사항은 공식 저장소에서 확인한다.[^repo]

| 단계 | 사용하는 정보 | 결과 |
|---|---|---|
| 사전학습 | 다양한 합성 표 예측 문제 | 여러 문제에 적용할 모델의 가중치 |
| 새 프로젝트 적용 | 현재 학습 행의 특성과 정답, 새 행의 특성 | 새 행의 예측 |
| 성능 평가 | 예측 시 숨겨 둔 검증·테스트 정답 | 새로운 관측에서의 성능 추정 |

여기서 새 프로젝트의 학습 정답은 예측할 때 문맥에 포함되는 반면, 검증과 테스트의 정답은 성능을 계산할 때만 사용한다.
검증 정답으로 계산한 성능은 모델과 설정의 선택에 쓰이고, 테스트 정답은 선택이 끝난 뒤의 최종 평가에 사용한다.
분할을 바꾸면 그 분할의 학습 행만 문맥에 넣어 새로 검증한다.

새 행의 정답은 예측할 때 모델에 제공하면 안 된다.
표에서 다른 정보가 새 행의 결과를 이미 드러내는지도 확인해야 한다.
예를 들어 결과가 기록된 뒤에 만들어지는 열은 실제 예측 시점에 이용할 수 없다.

## 3. 후보 모델의 공정한 비교

### 3.1 평가 조건과 비교

목표가 몸무게 예측이라면 선형회귀, XGBoost, TabPFN이 같은 목표와 같은 학습·검증·테스트 분할을 사용해야 한다.
학습 행이 다르거나 한 모델에만 사후 정보를 넣으면 모델 자체의 비교가 아니다.
전처리는 각 모델의 요구에 맞게 달라질 수 있지만, 각각 학습 부분에서만 맞추고 차이를 기록한다.
동일한 분할에서 MAE와 RMSE(root mean squared error)를 계산하고, 예측 한 건을 만드는 시간도 측정한다.
RMSE는 오차를 제곱한 뒤 평균하고 제곱근을 취하므로 원래 단위로 표현되며, 큰 오차에 MAE보다 민감하다.

가령 특정 하드웨어에서 학습 행 1,000개와 특성 10개를 쓰고 단일 관측을 예측한다고 가정하자.
다음 수치와 비용 순서는 그 환경을 설명하기 위해 임의로 만든 값이며 실제 측정 결과나 모델의 고유한 속도가 아니다.
하드웨어, 표 크기, 일괄 처리, 캐시와 구현에 따라 비용 순서도 달라질 수 있다.

| 후보 | 검증 MAE (g) | 예측 한 건의 상대 비용 | 살펴볼 점 |
|---|---|---|---|
| 학습 몸무게의 평균 | 520 | 낮음 | 아무 특성도 사용하지 않는 기준 |
| 선형회귀 | 310 | 낮음 | 단순한 관계로 설명 가능한가 |
| XGBoost | 280 | 중간 | 전처리와 초매개변수에 민감한가 |
| TabPFN | 275 | 높음 | 사전학습 모델의 추가 비용이 이득을 정당화하는가 |

이 표의 예측 비용은 준비가 끝난 모델로 한 건을 처리하는 비용을 뜻하며 사전학습과 현재 표의 준비 비용은 포함하지 않는다.
프로젝트에서 전체 소요 시간을 비교하려면 가중치 다운로드나 로딩, 현재 표의 준비, 예측 횟수에 따른 처리 시간을 각각 측정해야 한다.
한 번만 예측할 때와 수천 건을 여러 번 예측할 때는 준비 비용이 전체 시간에서 차지하는 비율이 달라진다.

TabPFN의 검증 MAE가 5 g 낮더라도 그 차이가 표본의 우연한 구성에 민감한지 살펴야 한다.
또한 예측 빈도가 높고 빠른 응답이 필요하다면 비용이 선택을 바꿀 수 있다.
같은 지표라도 중요 집단에서 오차가 큰 모델은 전체 평균만으로 선택하지 않는다.

### 3.2 반복 평가와 선택

같은 관측이 한 개체에서 반복 측정되었다면 행을 무작위로 나눌 때 같은 개체가 양쪽에 섞일 수 있다.
새 개체를 예측하려는 목표라면 개체 단위로 나누어야 한다.
미래를 예측한다면 시간 순서를 반영해야 한다.
독립적인 관측을 가정할 수 있는 상황에서는 학습·검증 분할을 여러 번 바꾸어 모델 차이가 일관적인지 살핀다.
어떤 경우든 최종 테스트 세트는 모델, 전처리, 지표를 결정하기 전에 선택에 사용하지 않는다.

분할을 반복하면 한 번의 우연에 덜 의존하는 비교를 할 수 있지만, 같은 데이터를 재사용한 결과들이 완전히 독립인 것은 아니다.
결과의 분포와 각 분할의 특성을 보고 과장된 확신을 피한다.
서로 다른 전처리와 데이터 버전에서 성능이 비슷한지도 확인하면 앞 노트의 PCS 안정성 평가와 연결된다.

## 4. 연구 결과와 적용 범위

TabPFN v2 논문은 작은 표 형식 데이터에 대한 분류와 회귀 벤치마크에서 부스팅을 포함한 방법과 비교했다.
논문에서 주로 평가한 범위는 최대 10,000개 행과 500개 특성이다.
해당 조건에서 강한 성능과 짧은 적합 시간을 보고했지만, 그 결과가 모든 표와 모든 크기에서 우위를 보장하는 것은 아니다.[^tabpfn]
특히 모델 준비 시간과 실제 새 관측을 예측하는 시간은 구별해야 한다.
논문은 개별 예측 속도나 큰 데이터에서의 메모리 비용이 제약이 될 수 있다고 설명한다.

이 논문의 수치와 조건은 **v2 실험에 해당**한다.
라이브러리의 기본 모델과 버전별 허용 범위, 하드웨어 요구 사항은 바뀔 수 있으므로 프로젝트에서는 실제 사용한 패키지 버전과 가중치 버전을 기록한다.
공식 저장소는 코드와 모델 가중치에 별도 라이선스가 적용된다고 안내한다.[^repo]
로컬 실행과 외부 서비스 호출은 데이터가 처리되는 위치도 다르므로, 공개할 수 없는 자료는 선택한 실행 방식과 이용 조건을 확인한 후 사용한다.

### 4.1 이후 버전과 비교의 조건

2026년 공개된 TabPFN-3 기술 보고서는 합성 데이터 사전학습과 문맥 학습을 유지하면서 더 큰 표에 적용하고 추론 비용을 줄이는 방향을 제시한다.[^tabpfn3]
저자들은 최대 100만 학습 행을 다루는 실험을 보고하지만, 이는 특정 하드웨어와 실험 설정에서 얻은 결과다.
v2 논문의 10,000행 평가 범위와 서로 다른 버전의 적용 범위를 같은 제한으로 혼동하지 않는다.
또 벤치마크에서 보고한 우위가 각자의 프로젝트에서도 유지되는지는 같은 분할과 계산 예산에서 직접 확인해야 한다.

후속 버전인 TabPFN-3.5도 공개되었다.[^tabpfn35]
공식 저장소는 최근 패키지의 기본 모델로 3.5를 안내하므로, `TabPFNClassifier()`나 `TabPFNRegressor()`를 버전 지정 없이 호출했다면 v2 또는 3의 실험을 그대로 재현한다고 가정해서는 안 된다.[^repo]
실험 기록에는 패키지 버전과 실제 가중치 버전을 함께 남긴다.

버전은 사용 조건도 바꾼다.
예를 들어 TabPFN-3의 모델 카드에 따르면 해당 가중치는 연구와 제한된 내부 평가를 허용하지만 상업적·운영 목적 사용은 별도 조건을 확인해야 한다.[^tabpfn3-card]
패키지 설치만으로 특정 가중치의 사용 권한이나 데이터 외부 전송 여부가 정해지는 것은 아니므로, 선택한 가중치와 실행 방식의 조건을 각각 확인한다.

## 5. 프로젝트에서의 선택

표 형식 파운데이션 모델을 후보로 넣을 때에도 앞 노트의 절차를 따른다.
문제의 사용 시점과 허용 입력을 정하고, 단순 기준 모델과 기존 모델을 같은 분할에서 비교한다.
검증 결과뿐 아니라 데이터 섭동, 계산 비용, 사용 조건을 함께 보고 하나의 모델이나 앙상블을 선택한다.
마지막으로 보존한 테스트 자료에서 선택한 결과를 평가한다.

모델의 예측에 SHAP 등을 적용할 때는 설명이 모델과 배경 데이터의 선택에 의존한다는 점도 기억한다.
서로 다른 모델에서 같은 변수의 기여가 다르다면 어떤 예측 함수를 설명하는지와 특성 간 관계를 먼저 살펴야 한다.
설명에서 기여가 크다는 사실은 그 특성을 바꾸면 결과가 원인적으로 바뀐다는 증거가 아니다.

다음 주에는 관측의 순서가 중요한 시계열과 이벤트 예측을 다룬다.
그 경우 임의의 행 분할이 아닌 실제 미래 예측 상황에 맞는 평가가 출발점이 된다.
