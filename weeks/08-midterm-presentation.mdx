중간 발표에서는 제안 이후 확보한 자료와 실제 실행 결과를 보여 주고, 남은 모델링·평가
계획을 갱신한다. 미실행 항목을 결과처럼 제시하지 않는다. 발표 시간·제출 기한·파일
형식과 Quiz 2의 문항·배점은 별도 공지를 따른다.

## 1. 계획과 현재 상태를 비교하기

| 항목 | 발표에서 보여 줄 것 |
|---|---|
| 질문 변경 | 제안 때 질문, 현재 질문, 바뀐 이유 |
| 자료 범위 | 실제 확보 기간·독립 단위 수·변수·누락과 이용 조건 |
| 정제 | 원자료에서 분석 표까지의 변환과 행 수 변화 |
| 탐색 | 핵심 질문별 그림, 관측된 사실, 대안 설명 |
| 평가 준비 | baseline, 분할 경계, primary metric, 아직 열지 않은 test |
| 남은 작업 | 가장 큰 불확실성, 확인 실험, 담당자와 일정 |

Cleaning 함수가 실행된다는 사실과 판단이 타당하다는 사실을 구분한다. 제외한 행이
어떤 집단·날짜에 몰렸는지, 전처리 대안에서 EDA 결론이 달라지는지 함께 보여 준다.

## 2. 그림 하나를 끝까지 설명하기

가상으로 12시대의 대기가 더 길어 보인다면, 축·단위·기간·분모를 먼저 읽는다. 행사일을
제외해도 차이가 남는지, 식당 구성이 달라 생긴 차이인지 확인한다. “점심이라 길어진다”는
원인 주장과 “관측한 12시대의 중앙값이 더 크다”는 기술을 구분한다.

각 핵심 그림에 다음 세 문장을 붙인다.

1. 이 그림에서 직접 확인한 것은 무엇인가.
2. 어떤 선택이나 누락 때문에 해석이 달라질 수 있는가.
3. 다음 분석에서 무엇을 확인할 것인가.

## 3. 후반부 실행 계획 확정하기

현재 구현했다면 baseline 결과와 재실행 근거를 보여 준다. 아직 구현하지 않았다면
필요한 입력과 실행 계획을 명시한다. 불완전한 결과를 감추기 위해 독립 test를 열어
모델이나 질문을 고르지 않는다.

발표 후 피드백을 `문제 → 조치 → 담당자 → 확인 시점 → 완료 근거`로 기록한다.
남은 기간에 해결하기 어려운 자료 문제는 모델 복잡도를 올리는 계획으로 대신하지 말고,
적용 대상이나 질문을 줄이는 방안을 함께 검토한다.
