[05a](./05a-data-collection-and-ethics)에서는 데이터를 만드는 사람의 자리에서 수집 설계를 보았다. 이 노트는
데이터를 받은 사람의 자리로 옮겨, 받은 데이터를 분석할 수 있는 상태로 만드는 과정을 다룬다. 절차와 점검
목록은 교재 4장에서 가져오고, 예시는 K-EmoCon의 데이터 문서와 저자들이 공개한 코드에서 실제로 마주치는
문제로 든다.

이 과정에서 하는 일은 기술적으로 단순해 보인다. 열 이름을 바꾸고, 빈칸을 채우고, 시간을 맞춘다. 그런데
그 하나하나가 결과를 바꿀 수 있는 **판단**이다. 3주차 사례 연구가 정제·전처리 판단마다 근거를 적어 둔
이유도 여기에 있다([3주차 §5](./03-project-setup-and-feasibility#5-정제와-전처리)). 이번 노트의 목표는 판단을
찾아내고, 대안과 함께 기록하고, 나중에 대안을 바꿔 결과를 다시 볼 수 있게 코드로 남기는 것이다.

**읽기 자료**: 교재 4장 [Data Preparation](https://vdsbook.com/04-data_cleaning).[^vds4]

## 1. 정제와 전처리

교재는 데이터 준비(data preparation)를 두 단계로 나눈다.[^vds4]

- **정제(data cleaning)**: 데이터를 모호하지 않게 고쳐, 사람과 컴퓨터가 모두 올바르게 읽을 수 있게 만든다.
  K-EmoCon이라면 손목밴드 가속도 원값에 1/64를 곱해 중력가속도(g) 단위로 바꾸고, 뇌파 헤드셋의 집중도
  지수에서 "측정 불가"를 뜻하는 0을 결측으로 표시하는 일이다.
- **전처리(preprocessing)**: 정제된 데이터를 특정 알고리즘이나 분석이 요구하는 형태로 바꾼다. 결측을
  허용하지 않는 알고리즘을 위해 결측을 채우거나, 5초 구간마다 신호를 요약해 모델의 입력 한 줄로 만들거나,
  변수의 척도를 맞추는 일이다.

둘을 나누는 기준은 **목적**이다. 정제는 어떤 분석을 하든 필요하고, 전처리는 이번에 쓸 방법에 따라 달라진다.
같은 결측이라도 `NA`로 바르게 표시하는 것은 정제이고, 그 `NA`를 앞 값으로 채우는 것은 전처리다. 실제로는
경계가 흐려서 교재도 하나의 함수로 둘을 함께 처리해도 된다고 말한다. 그래도 구분해 두면 판단이 어디서
생기는지 보인다. 정제는 데이터 자체에 대한 판단이고, 전처리는 분석 방법에 딸린 판단이다.

교재가 강조하는 원칙은 세 가지다.

1. **원본 파일은 고치지 않는다.** 정제는 프로그램 안에 불러온 사본에만 적용한다.
2. **깨끗한 버전은 하나가 아니다.** 합리적인 판단이 여러 개면 정제된 데이터도 여러 버전이 나온다.
3. **판단은 기록하고, 대안은 코드로 남긴다.** 판단을 함수의 인자로 만들어 두면 다른 버전을 쉽게 만들고,
   결론이 판단에 따라 흔들리는지 확인할 수 있다. 2주차에서 본 PCS의 stability가 이 확인이다.

## 2. 절차와 점검 목록

[05a §1-1](./05a-data-collection-and-ethics#11-4단계-절차)에서 본 데이터 준비의 네 단계 중 1단계(이해하기)는
05a에서 K-EmoCon 논문을 읽으며 했다. 이 노트는 나머지 세 단계를 밟는다.

2. **불러오기.** 파일을 읽은 뒤 행·열 수가 문서에서 예상한 값과 맞는지 확인한다. 맞지 않으면 바로 고치지
   말고 질문으로 적어 둔다. 교재 §4.4.1의 장기기증 데이터도 이 확인에서 첫 단서가 나온다.
3. **살펴보고 할 일 정하기.** 아래 점검 목록을 훑으며 고칠 것을 할 일(action item) 목록으로 만든다. 대안이
   둘 이상인 할 일은 판단으로 따로 표시한다.
4. **정제하기.** 할 일을 함수로 구현하고, 판단은 인자로 둔다(§5).

데이터를 학습용과 평가용으로 나눌 계획이라면 순서에 주의한다. 정제·전처리 규칙은 학습용 데이터만 보고 정하고,
평가용 데이터에는 **학습용에서 실제로 한 처리를 그대로** 적용한다(교재 §4.2). 학습용에서 결측이 많아 지운 열,
채우는 데 쓴 값, 표준화에 쓴 평균과 표준편차를 평가용에서 다시 계산하지 않는다. 평가용으로 다시 계산하면 두
데이터의 열 구성이나 척도가 달라질 수 있고, 평가용 데이터의 정보가 처리 과정에 새어 들어간다. K-EmoCon처럼
참가자가 적은 데이터는 참가자 단위로 나누는 경우가 많으니, 기준선 보정 같은 참가자별 처리와 전체 데이터에서
정하는 처리를 구분해 둔다.

3단계에서 점검할 흔한 증상을 교재는 여섯 가지로 묶는다(교재 §4.5). 아래 표의 오른쪽 열은 K-EmoCon 논문의
Data Records 절에서 찾은 실제 예다.[^kemocon]

| 증상 | 점검할 것 | K-EmoCon에서 보면 |
|---|---|---|
| 잘못되거나 모순된 값 | 값의 범위가 분야 지식과 맞는가, 단위가 섞이지 않았는가 | 가속도 원값은 64가 1 g에 해당하는 단위라 그대로 쓰면 크기를 64배로 읽게 된다 |
| 결측의 표시 방식 | 결측이 `NA` 대신 특정 숫자나 문자로 적혀 있지 않은가 | 집중도·이완도 지수의 0은 "기기가 믿을 만한 값을 계산하지 못함"이라는 뜻이다. 진짜 0이 아니다 |
| 표준이 아닌 형식 | 한 행이 관측 단위 하나이고 한 열이 측정 하나인가(tidy 형식)[^tidy] | 외부 평가가 참가자·평가자마다 파일 하나(`P<X>.R<Z>.csv`)로 흩어져 있다. 합치면 관측 단위는 (참가자, 5초 구간, 평가자)가 된다 |
| 지저분한 열 이름 | 사람이 읽을 수 있고 일관된 이름인가 | 열 이름은 정돈된 편이다. 대신 영상 길이처럼 파일 이름(`p<X>_<T>.mp4`)에만 있는 정보를 열로 꺼내야 한다 |
| 맞지 않는 변수 유형 | 각 열의 유형이 그 열이 재는 것과 맞는가 | 시각은 UTC 기준 밀리초 단위 숫자다. 구간을 고를 때는 숫자 그대로 비교해도 되고, 초 단위로 다시 샘플링하는 등 시간 연산이 필요하면 날짜·시간 유형으로 바꾼다. 범주형 감정은 여러 열 중 한 곳에 `x`를 찍는 식으로 기록돼 있어 범주 하나를 담은 열로 바꿀 수 있다 |
| 불완전한 데이터 | 모든 관측 단위가 정확히 한 번씩 있는가, 행 수가 예상과 맞는가 | 참가자별로 어떤 파일이 있는지는 `data_availability.csv`가 알려 준다. 같은 참가자의 평가 파일끼리도 행 수가 다를 수 있다(§4-2) |

표의 마지막 행이 특히 위험하다. 행 자체가 빠진 관측 단위는 결측 비율을 세어도 드러나지 않는다. 있어야 할
관측 단위의 목록을 먼저 만들고(예: 참가자 32명 × 5초 구간), 데이터와 대조해야 보인다.

변수 유형은 분석에 따라 다르게 정할 수 있다. 각성도처럼 순서가 있는 1–5 점수는 순서 있는 범주로 둘 수도
있고 숫자로 둘 수도 있다. 숫자로 두면 평균을 낼 수 있지만, 1과 2 사이와 4와 5 사이의 간격이 같다는 가정이
따라온다. 이 가정이 분석에 필요한지에 따라 고른다.

## 3. 결측 다루기

결측은 정제와 전처리 양쪽에 걸친다. 교재의 권고를 요약하면 다음과 같다.

- **정제 단계에서는 표시만 한다.** 결측을 뜻하는 0이나 `999`를 `NA`로 바꾸되, 지우거나 채우지는 않는다.
- **행을 지우면 결론의 범위가 좁아진다.** 값이 빠졌다는 사실 자체가 정보일 수 있다. 특정 조건의 관측만
  체계적으로 빠졌다면, 결측 행을 지운 데이터는 그 조건을 덜 대표한다. 지웠다면 결론이 적용되는 범위를 그만큼
  좁혀 말한다.
- **채우기(imputation)는 분야 지식으로 고른다.** 일반적으로 행 삭제보다 편향이 적지만, 무엇으로 채울지는
  데이터가 어떻게 만들어졌는지에 달려 있다.
- **라이브러리에 맡기지 않는다.** 결측을 허용하는 것처럼 보이는 함수도 내부에서 결측 행을 조용히 지우는
  경우가 많다. 결측 처리는 전처리 함수에서 직접 하고 기록한다.

K-EmoCon의 집중도 지수로 해 보자. 1초마다 기록된 값이 52, 0, 0, 61이라면 먼저 0 두 개를 `NA`로 바꾼다(정제).
분석에 쓰려고 채운다면 선택지가 여럿이다(전처리, 교육용 가상 예시).

| 채우는 방법 | 결과 | 가정 |
|---|---|---|
| 앞 값으로 채우기 | 52, 52, 52, 61 | 측정이 안 된 동안 상태가 그대로였다 |
| 시간에 따른 선형 보간 | 52, 55, 58, 61 | 상태가 일정한 속도로 변했다 |
| 채우지 않고 그 구간을 분석에서 제외 | 52, 61 | 빠진 2초는 분석에 필요 없다 |

두 칸이 아니라 몇 분이 비어 있다면 이야기가 달라진다. 논문의 결측 설명을 보면 어떤 참가자는 집중도 지수의 59%가
빠졌다.[^kemocon] 이런 공백을 보간으로 메우면 측정하지 않은 값을 지어내는 셈이 된다. 그래서 "몇 초까지의 공백만 채우고
그보다 긴 공백은 결측으로 둔다"는 기준을 정하는 것도 판단이다. 결측이 너무 많은 신호는 그 참가자에게서
아예 빼거나, 신호 자체를 분석에서 빼는 선택도 있다. §4-3에서 이 선택이 참가자 수를 어떻게 바꾸는지 본다.

## 4. K-EmoCon에서 마주치는 판단

K-EmoCon은 05a에서 본 대로 저자들이 품질 정보를 꼼꼼히 공개한 데이터다. 그래도 받은 사람이 내려야 할
판단이 많다. 아래 내용은 논문의 Data Records 절과 저자들이 공개한 보조 코드(MIT 라이선스)를 직접 읽고
정리했다.[^kemocon][^kemocon-code]

### 4.1 시간축 맞추기

여러 장비의 기록을 함께 쓰려면 먼저 같은 시간축에 올려야 한다. 저자들은 모든 타임스탬프를 한국 표준시
(UTC+9)에서 UTC로 바꾸었다. 영상과 음성은 토론 구간만 잘라 공개했지만, 생체신호는 기록 시작부터 토론
종료까지 잘랐다. 그래서 생체신호 파일에는 기록 시작 직후의 기준선 측정과 토론 사이의 구간도 남아 있다. 논문은
이 사이 구간을 분석에서 빼도 된다고 적었다. 분석할 구간은 `subjects.csv`에 있는 참가자별 기록 시작, 토론
시작, 토론 종료 시각으로 다시 골라야 한다.

그다음 문제는 샘플링 주기다. 감정 평가 한 개는 5초 구간에 대응한다. 같은 5초 안에 각 신호의 값이 몇 개씩
들어 있는지 계산해 보자.

| 신호 | 샘플링 주기 | 5초 구간 하나의 값 개수 |
|---|---|---|
| 맥파(BVP) | 64 Hz | $64 \times 5 = 320$ |
| 가속도 | 32 Hz | $32 \times 5 = 160$ (축마다) |
| 피부전도 | 4 Hz | $4 \times 5 = 20$ |
| 피부 온도 | 4 Hz | $4 \times 5 = 20$ |
| 가슴 센서 심박 | 1 Hz | $1 \times 5 = 5$ |

5초 구간 하나를 모델의 입력 한 줄로 만들려면 길이가 제각각인 이 값들을 어떻게 요약할지 정해야 한다. 평균,
표준편차, 최댓값 같은 통계량을 뽑을 수도 있고, 같은 주기로 다시 샘플링할 수도 있다. 이 판단은 §6에서 보듯
6주차 탐색적 데이터 분석과 모델링 주차에서 다시 다룬다.

공식 전처리 코드에는 데이터 문서에 없는 판단도 들어 있다.

- **가슴 센서 심박의 중복 기록.** 1 Hz로 기록돼야 하는데 1초 안에 값이 여러 개 들어간 구간이 있다. 코드는
  1초 단위로 평균을 내고 빈 초는 시간에 따라 선형으로 보간한다. 평균 대신 첫 값이나 중앙값을 쓸 수도 있다.
- **두 기기가 섞인 파일.** P29–P32의 손목밴드 파일에는 기기 일련번호가 두 개 섞여 있다. 논문은 참가자별로 쓸
  일련번호를 권하고, 코드도 분석에 쓰는 P31, P32에 대해 그 번호의 행만 남긴다.
- **기준선 길이.** 논문은 기록 시작 직후 1.5–2분이 기준선이라고 적었고, 코드는 기록 시작부터 정확히 2분을
  잘라 쓴다.

### 4.2 평가 길이 맞추기

한 참가자에 대한 본인·상대방·외부 평가 파일의 행 수가 서로 다를 때가 있다. 논문은 긴 파일을 **앞에서부터**
잘라 짧은 파일에 맞추라고 권한다. 참가자가 기준선 측정 구간을 토론으로 착각해 평가를 먼저 시작했을 가능성이
있다는 이유다.

예를 들어 본인 평가가 122행, 상대방 평가가 120행이라면 본인 평가의 처음 두 행(첫 10초)을 버린다(교육용
가상 예시). 뒤에서 자르거나, 시작 시각을 기준으로 정렬하는 다른 선택도 가능하다. 앞에서 자른다는 것은
"초과분은 시작 부분의 실수에서 왔다"는 가정을 받아들인다는 뜻이다. 공식 코드는 여기서 한 걸음 더 나아가,
평가 길이를 생체신호가 실제로 겹치는 구간에 맞추면서 남는 부분을 앞뒤 공백의 비율대로 나누어 잘라 낸다.

### 4.3 참가자 고르기

공식 코드는 32명 중 **21명**만 남긴다. 코드에 적힌 참가자 목록과 논문의 결측 설명을 대조하면 기준이
보인다. 맥파, 피부전도, 피부 온도, 가슴 센서 심박 네 신호 중 하나라도 통째로 빠진 참가자를 모두 뺐다.

| 빠진 이유 | 참가자 |
|---|---|
| 손목밴드 고장(맥파·피부전도·온도 모두 없음) | P2, P3, P6, P7 |
| 피부전도 없음 | P17, P20 |
| 가슴 센서 심박 없음 | P3, P12, P18, P20, P21, P29, P30 |

겹치는 사람(P3, P20)을 한 번씩 세면 11명이 빠지고 21명이 남는다. 공개된 영상도 21명분이지만 영상 공개에
동의한 사람과 이 21명이 같은 집단이라는 근거는 없다. 숫자가 같을 뿐 기준이 다르다.

이 판단은 §3에서 본 **행 삭제**다. 빠진 11명은 기기 고장이나 접촉 불량 때문에 빠졌으니 감정과는 관계가
없어 보인다. 하지만 접촉 불량이 피부 상태처럼 생리 반응과 관련된 특성 때문이었다면, 남은 사람의 생리 반응
분포는 원래와 조금 다를 수 있다. 확실히 알 수는 없으므로, 결론을 말할 때 "21명"이라는 범위를 밝혀야 한다.

대안도 있다. 가슴 센서 심박을 쓰지 않고 손목밴드 신호(맥파, 피부전도, 온도)만 쓰면 P2, P3, P6, P7, P17, P20의
6명만 빠져 **26명**이 남는다(논문의 결측 목록으로 새로 계산한 값). 신호 하나를 포기하고 참가자 5명을 더
얻는 셈이다. 어느 쪽이 나은지는 연구 질문이 정한다. 심박을 두 장비로 교차 확인하는 것이 중요하면 21명,
참가자 수가 중요하면 26명이다. 두 버전 모두로 분석해 결론이 같은지 보는 것이 PCS가 권하는 방식이다.

### 4.4 여러 평가자의 판단 합치기

외부 평가자 5명의 평가는 공개 데이터에 개별 파일로도, 다수결로 합친 파일로도 들어 있다. 공식 코드의 설명에
실린 예를 보면, 어떤 5초 구간의 각성도를 다섯 명이 3, 1, 1, 1, 1로 평가했다면 최빈값인 1이 합친 값이 된다.

여기에도 판단이 있다.

- **동점 처리.** 3, 3, 1, 1, 2처럼 최빈값이 둘 이상이면 코드는 그중 하나를 **무작위로** 고른다. 난수 시드를
  고정하지 않으므로 코드를 다시 돌리면 합친 값이 달라질 수 있다. 공개된 합친 파일은 그 무작위 선택 중 한
  번의 결과다.
- **합치는 방식.** 각성도와 쾌-불쾌는 1–5의 순서가 있는 척도이니 다수결 대신 중앙값을 쓸 수도 있다. 3, 1, 1,
  1, 1이면 다수결과 중앙값이 모두 1이지만, 3, 3, 1, 1, 2라면 중앙값은 2이고 다수결은 3이나 1 중 하나다.
- **합칠지 말지.** 평가자 사이의 차이 자체가 연구 대상이라면 합치지 않고 다섯 명의 평가를 그대로 둔다.

또 하나의 판단은 평가자 사이의 **일치도**를 계산할 때 나온다.
[05a §3-6](./05a-data-collection-and-ethics#36-감정-평가)에서 다섯 감정(쾌활함·행복·분노·긴장·슬픔)은 1–4
척도라 중립이 없다고 했다. 저자들이 든 예를 보자. 어떤 참가자가 자신의 쾌활함을 토론 전반부에 1, 후반부에
2로 평가했고, 상대방은 같은 참가자를 전반부 3, 후반부 4로 평가했다. 둘 다 "후반부에 더 쾌활했다"고 본
것인데, 값 자체가 2씩 차이 나서 일치도를 그대로 계산하면 0에 가깝게 나온다.

저자들은 이 문제를 줄이려고 각 평가 파일의 감정 열마다 최빈값을 중립으로 보고 빼는 **최빈값 빼기**(mode-subtraction)를
적용했다. 위 예에서 전반부가 조금 더 길다면 본인의 최빈값은 1, 상대방의 최빈값은 3이고, 빼고 나면 두 사람
모두 0, 1이 되어 변화의 방향이 맞는다. 그 대신 이렇게 계산한 일치도는 "감정의 변화에 대한 합의"를 재는
것이지 "감정의 수준에 대한 합의"를 재는 것이 아니다. 상대방이 참가자를 실제로 더 쾌활하게 봤을 가능성은 이
처리로 지워진다. 저자들도 이 처리가 자기 용도에 맞는지 사용자가 판단하라고 적었다.

<Callout type="example">
같은 원자료에서 출발해도 전처리 판단이 달라지면 질문이 달라진다. 최빈값 빼기를 한 데이터는 "감정이 언제
변했는가"에 답하기 좋고, 하지 않은 데이터는 "누가 감정을 더 강하게 보았는가"에 답하기 좋다. 전처리는
분석 방법에 딸린 판단이라는 §1의 구분이 이런 뜻이다.
</Callout>

### 4.5 이상치와 품질 표

[05a §4](./05a-data-collection-and-ethics#4-공개된-데이터)에서 본 품질 표의 이상치 개수는 Chauvenet
기준(Chauvenet's criterion)으로 셌다. 값이 $N$개 있을 때, 정규분포라면 그 값만큼 평균에서 멀리 떨어진 값이
$N$개 중 0.5개도 나오지 않을 것으로 기대되면 이상치로 본다. 식으로 쓰면 표준화 거리 $z = |x - \bar{x}| / s$에
대해 다음을 만족하는 값이다.

$$
N \cdot P(|Z| > z) < 0.5
$$

$N$이 클수록 기준이 엄해진다. 4 Hz로 10분 기록한 피부전도처럼 값이 2,400개라면, 평균에서 표준편차의 약
3.71배를 넘어야 이상치다(새로 계산한 값).

<Details summary="공식 코드의 기준은 이 정의와 다르다">

정규분포에서 $P(|Z| > z) = \operatorname{erfc}(z/\sqrt{2})$다. 공식 코드는 이 확률을
`erfc(d)`로 계산한다(`d`는 위의 $z$). $\sqrt{2}$로 나누는 부분이 빠져 있어, 실제로는 표준편차의 $3.71/\sqrt{2} \approx 2.62$배만
넘어도 이상치로 센다. 품질 표의 이상치 개수가 표준 정의보다 많게 나왔을 수 있다는 뜻이다. 이 차이는 코드를
직접 읽어야 보인다. 데이터 문서와 코드를 그대로 믿지 말고 확인하라는 교재 §4.3의 조언이 여기에도 해당한다.

</Details>

이상치 개수가 정확하더라도 판단은 남는다. Chauvenet 기준은 값이 정규분포를 따른다고 가정하지만, 피부전도처럼
한쪽으로 긴 꼬리를 가진 신호는 정상적인 반응도 이상치로 잡힐 수 있다. 교재가 강조하듯 예상 밖의 값과 잘못된
값은 다르다. "기준을 넘었다"는 조사할 신호이지 바로 지울 이유가 아니다. 땀이 나서 피부전도가 갑자기 오른
순간이 바로 우리가 찾는 감정 반응일 수도 있다.

## 5. 판단을 함수로 남기기

교재는 정제·전처리를 **함수 하나**로 만들고, 판단마다 인자를 두라고 권한다(교재 §4.6). 정제된 파일을
저장해 두고 불러 쓰는 대신 매번 원본에서 함수로 만들어 쓴다. 그래야 판단 하나를 바꾼 버전을 바로 만들 수 있다.

작은 판단 하나부터 함수로 만들어 보자. §4-4의 외부 평가 합치기를 함수로 쓰면 다음과 같다. 이 코드는 그대로
실행된다.

```python
import numpy as np
import pandas as pd

def merge_raters(scores, rng, method="majority"):
    """한 5초 구간에 대한 여러 평가자의 순서형 점수를 하나로 합친다."""
    scores = pd.Series(scores)
    if method == "median":
        return float(scores.median())
    modes = scores.mode().to_numpy()            # 최빈값이 여럿이면 모두 돌려준다
    return int(rng.choice(modes))               # 동점이면 하나를 무작위로 고른다

rng = np.random.default_rng(seed=0)             # 전체 처리에서 한 번만 만든다
merge_raters([3, 1, 1, 1, 1], rng)                   # 1
merge_raters([3, 3, 1, 1, 2], rng, method="median")  # 2.0
merge_raters([3, 3, 1, 1, 2], rng)                   # 1 또는 3
```

`method`와 시드가 판단이다. 난수 생성기는 처리를 시작할 때 시드로 **한 번** 만들고 모든 구간에 같은 생성기를
넘긴다. 구간마다 같은 시드로 새로 만들면 동점일 때마다 같은 순위의 후보가 뽑혀, 무작위가 아니라 "항상 작은 값"
같은 규칙이 되어 버린다. 시드를 드러내 두면 공식 코드에서 숨어 있던 무작위성이 재현 가능한 선택으로 바뀐다.

데이터 전체를 준비하는 함수도 같은 방식으로 짠다. 아래는 구현을 생략하고 인자 구성만 보인 **골격**이다.

```python
                    mode_subtraction=False):                # §4-4: 일치도 분석용

```

`signals`를 `("bvp", "eda", "temp")`로 바꾸면 26명 버전이, `external_merge="median"`으로 바꾸면 중앙값 버전이
나온다.

함수와 함께 **판단 기록표**를 남긴다. 3주차 사례 연구의 표가 바로 이런 기록이다.

| 판단 | 택한 값 | 대안 | 근거 | 결과에 주는 영향 확인 |
|---|---|---|---|---|
| 분석할 참가자 | 네 신호가 모두 있는 21명 | 손목밴드 신호만 쓰는 26명 | 심박을 두 장비로 교차 확인 | 두 버전으로 주요 결과 비교 |
| 외부 평가 합치기 | 다수결, 시드 0 | 중앙값, 시드 변경 | 공개 파일과 같은 방식 | 합친 값이 달라지는 구간 비율 |
| 평가 길이 맞추기 | 앞에서 자르기 | 뒤에서 자르기 | 논문의 권고 | 잘린 구간 수 |

마지막 열이 비어 있는 판단은 아직 끝나지 않은 판단이다. 영향 확인은 6주차 탐색과 이후 모델링 주차에서
채워 나간다.

교재 §4.7은 특정 알고리즘이 요구하는 전처리를 따로 꼽는다. 이번 주에는 이름만 알아 두고, 필요한 주차에서

## 7. 우리 데이터의 정제 계획

이번 주 활동은 팀 데이터로 §2의 2–4단계를 실제로 밟는 것이다.

1. **불러오고 확인한다.** 행·열 수를 데이터 문서에서 예상한 값과 비교하고, 다르면 질문으로 기록한다.
2. **여섯 증상을 점검한다.** §2의 표를 따라 점검하고, 발견한 문제를 할 일 목록으로 만든다.
3. **판단을 찾는다.** 할 일 중 합리적인 대안이 둘 이상인 것을 골라 판단 기록표에 적는다.
4. **함수로 만든다.** 원본을 입력으로 받아 정제된 데이터를 돌려주는 함수를 만들고, 판단 두 개 이상을
   인자로 둔다. 함수는 팀 repository의 함수 폴더에 두고 원본 데이터는 커밋하지 않는다.

**완료 기준**: 같은 원본에서 판단만 바꾼 두 버전의 데이터를 함수 호출 두 번으로 만들 수 있고, 판단 기록표에
최소 두 행이 있으면 된다. 이 두 버전은 6주차 탐색적 데이터 분석(exploratory data analysis, EDA)에서 결과를
비교하는 출발점이 되고, 8주차 M2 발표의 데이터 절로 이어진다.
