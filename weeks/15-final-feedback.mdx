이번 주에는 최종 발표와 보고서의 주장이 실제 근거와 맞는지 검토한다. 새 모델을
추가하는 일보다 현재 결론의 오류·누락을 먼저 해결한다. 피드백 진행 방식과 자료
제출 기한은 별도 공지를 따른다.

## 1. 주장마다 근거를 연결하기

| 초안의 주장 | 확인할 근거 |
|---|---|
| baseline보다 개선됐다 | 같은 평가 행·target·metric의 비교 |
| 특정 집단에서도 유효하다 | 해당 집단의 분모·오류·불확실성 |
| 분석 선택에 안정적이다 | 실제 수행한 perturbation과 뒤집힌 결과 |
| 사용자에게 도움이 된다 | 의사결정 비용·사용성 근거와 아직 검증하지 않은 효과 |
| 재현할 수 있다 | 새 세션 실행 기록·환경·자료 접근 조건 |

근거가 없으면 수행 가능한 확인을 추가하거나 주장 범위를 줄인다. 예측 오차 개선을
현실의 대기 감소나 비용 절감으로 바꾸어 쓰지 않는다.

## 2. 수정 우선순위 정하기

잘못된 label, 평가 누수, 단위 오류처럼 결론을 바꾸는 문제를 먼저 처리한다. 다음으로
누락된 baseline·분모·한계를 보완하고, 마지막으로 그림과 문장을 다듬는다.

| 피드백 | 조치 | 완료 근거 | 남은 제한 |
|---|---|---|---|
| 식당별 표본 수가 보이지 않는다 | 결과표에 날짜·구간 수 추가 | 갱신한 결과 파일 | 새 식당은 미평가 |

Test 결과를 보고 feature나 모델을 바꾸려면 기존 test를 개발 자료로 재분류하고 새 평가
자료를 마련한다. 확보하지 못했다면 기존 독립 평가 결과와 후속 개발 결과를 구분하고,
수정 모델의 독립 성능은 미확인이라고 명시한다.

## 3. 최종본 연결 확인

발표의 숫자, 보고서의 표, 코드가 생성한 결과가 같은 데이터·모델 version인지 대조한다.
팀원 한 명이 핵심 표를 재생성하고 다른 팀원이 설명 문장을 검토한다. 해결하지 못한
피드백은 삭제하지 않고 최종 한계와 후속 과제로 남긴다.
